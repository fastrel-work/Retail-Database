Retail Sales & Customer Analytics — SQL Portfolio Project

Project Overview

This project demonstrates my ability to design and analyze a relational retail database using **MySQL and MySQL Workbench**.

I began with raw retail CSV datasets and built a relational database from the ground up. This included defining tables, selecting appropriate data types, establishing primary and foreign keys, creating table relationships through an EER diagram, importing the data, and validating the completed database structure.

After building the database, I developed a series of SQL analyses designed around realistic business questions involving:

- Revenue performance
- Product profitability
- Category performance
- Product return rates
- Discount impact
- Month-over-month sales growth
- Repeat customer behavior
- Customer inactivity
- Revenue concentration

The purpose of the project was not only to practice SQL syntax, but to use SQL as an analytical tool for transforming transactional retail data into meaningful business insights.

Database Design

The project uses five primary tables:

| Table | Purpose |
|---|---|
| `customers` | Stores customer identifiers and customer information |
| `orders` | Stores individual orders, customer relationships, and order dates |
| `order_details` | Stores product-level transaction details such as quantity, price, cost, discounts, and returns |
| `products` | Stores product information and category relationships |
| `catagories` | Stores product category information |



Database Relationships

The relational structure follows:

    customers
        |
        | Customer_ID
        v
      orders
        |
        | Order_ID
        v
    order_details
        |
        | Product_ID
        v
      products
        |
        | Catagory_ID
        v
    catagories

Key relationships include:

- One customer can place multiple orders.
- One order can contain multiple order-detail records.
- Each order-detail record references a product.
- Each product belongs to a product category.

This structure allowed transactional data to be analyzed across customers, orders, products, and categories without unnecessarily duplicating information.
